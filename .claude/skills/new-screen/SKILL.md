# Новый экран

Правила целиком — в CLAUDE.md. Здесь порядок, по которому идти.

1. **Продукт и бренд.** Открой `apps/<продукт>/product.json`: какой бренд, какие экраны уже есть.
   Тексты будут по `system/brands/<бренд>/voice.md` и `glossary.md`.
2. **Шаблон.** Выбери в `system/core/patterns/` (list, record, form, settings) и открой его пример —
   экран продукта, указанный в шаблоне. Раскладку бери оттуда.
3. **Компоненты.** В `system/generated/snapshot.json` — только `ready` и `stable`, свойства только из `props`.
   Перед каждым компонентом прочитай «Правила» его контракта в `system/core/contracts/`.
4. **Чего нет.** Не рисуй своё. Заведи `system/core/candidates/C-<номер>-<имя>.md` по README в той же папке,
   на экране поставь то, что есть, и скажи об этом в отчёте.
5. **Файлы — все три сходятся:** `src/screens/<Name>Screen.tsx` (каркас `Page`, до 250 строк),
   маршрут в `src/main.tsx`, строка в `product.json` с `pattern`. Данные — в `src/data.ts`.
   Пункт в навигации — только если человек просил.
6. **Слова.** Сверь каждую подпись со словарём бренда: колонка «не пишем» — запрещена,
   у кнопки глагол действия, у ошибки — как исправить.
7. **Проверка.** `npm run check` → код 0. Хуки проверяют и сами: после каждой правки и перед «готово».
   Код 1 — исправь экран. Код 2 или 3 — остановись и скажи человеку.
8. **Отчёт** — по форме из CLAUDE.md: экран и шаблон; компоненты с уровнями; правила «человек»
   и «совет», которые учёл; слова из словаря; кандидаты; что сказал `npm run check`.
   Коммит делает человек.
