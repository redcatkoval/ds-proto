# ds-proto — правила для агента

Дизайн-система, общая для всех брендов, и продукты, собранные из неё.
Ты работаешь в продукте и собираешь экраны только из системы.

## Где что лежит

| что | где | можно менять |
|---|---|---|
| снимок: компоненты, свойства, уровни, где что используется | `system/generated/snapshot.json` | нет, собирается `npm run check` |
| контракты: правила применения компонентов | `system/core/contracts/<slug>.md` | нет, без просьбы человека |
| правила компонентов для линтера | `system/core/rules/<slug>.json` | нет |
| общие правила кода продуктов | `system/core/code-rules.json` | нет |
| шаблоны экранов | `system/core/patterns/*.md` | нет |
| токены: примитивы и роли | `system/core/tokens/*.json` | нет |
| разрешённый долг | `system/core/baseline.json` | никогда — только человек |
| кандидаты: чего в системе нет | `system/core/candidates/` | да, заводить новые |
| бренд: токены бренда и формулировки | `system/brands/<id>/brand.json` | нет |
| бренд: тон голоса, словарь, изображения | `system/brands/<id>/*.md` | нет |
| бренд: правила кода (словарь как проверка) | `system/brands/<id>/rules.json` | нет |
| бренд: иллюстрации | `system/brands/<id>/illustrations/` | нет |
| компоненты | `packages/ui/src/components/` | нет, без отдельного решения |
| продукт | `apps/<продукт>/src/` | да |
| описание продукта: бренд, экраны, их шаблоны | `apps/<продукт>/product.json` | да, при новом экране |
| правила кода продукта | `apps/<продукт>/rules.json` | нет — их добавляет команда продукта |

Продукт живёт под одним брендом — он указан в `product.json`, оттуда же
бренд берёт `src/main.tsx`. Тексты в продукте пиши по тону голоса и словарю
этого бренда.

## Как собрать экран

0. Выбери шаблон экрана в `system/core/patterns/` (список, карточка записи,
   форма, настройки) и открой его пример в продукте. Раскладку бери оттуда,
   не изобретай свою. Шаблон экрана укажи полем `pattern` в `product.json`.
1. Прочитай `system/generated/snapshot.json`. Бери компоненты с уровнем
   `ready` или `stable`. Черновик (`draft`) — только если человек прямо сказал.
2. Свойства — только те, что в снимке у компонента (`props`). Набор
   закрыт: `className`, `style` и чужих свойств нет.
3. Перед тем как поставить компонент, прочитай раздел «Правила» его
   контракта. Правила «Кто следит: машина» и «компонент» соблюдаются
   автоматически. Правила «человек» и «совет» — твоя ответственность:
   их перечисляешь в отчёте.
4. Слова в интерфейсе — из `system/brands/<id>/voice.md` и `glossary.md`.
   Кнопка — глагол из словаря, ошибка — как исправить. Слова из колонки
   «не пишем» словаря ловит проверка — во всех текстах продукта: в разметке,
   в подписях и `aria-label`, в строках `src/data.ts`.
   Пустое состояние — EmptyState с `illustration` из набора системы;
   свою картинку не вставляй.
5. Раскладка экрана — в CSS продукта, только семантические токены
   (`--color-*`, `--radius-*`, `--font-*`, `--shadow-*`, `--space-*`,
   `--font-size-*`). Цвета числом или именем не писать.
6. Каркас — `Page` из `src/Page.tsx` продукта. Новый экран: файл в
   `src/screens/`, маршрут в `src/main.tsx`, строка в `product.json` —
   все три сходятся, адрес `route` совпадает с путём маршрута.
   Пункт в навигации — только если человек просил.

## Чего нельзя (ловит проверка)

- голые `<button>`, `<input>`, `<select>`, `<textarea>`, `<table>` — есть компоненты;
- `style={{…}}` в коде продукта;
- цвет числом или именем (`#fff`, `rgb()`, `oklch()`, `color-mix()` с таким цветом,
  `red`, `white`; `transparent` и `currentColor` можно) и несуществующий токен в CSS продукта;
- файл экрана длиннее 250 строк — данные выносятся в `src/data.ts`;
- выдуманные свойства, компоненты, иконки — проверка типов;
- экран без шаблона в `product.json`;
- файл в `src/screens/` без строки в `product.json` или без маршрута в
  `src/main.tsx`; строка в `product.json` без файла.

## Не выдумывай

Если чего-то нет в снимке, контракте или текстах бренда — этого нет.
Не придумывай свойство, токен, слово или поведение компонента. Не уверен —
спроси человека или заведи кандидата.

## Чего в системе нет

Не рисуй недостающий компонент сам — ни в продукте, ни в `packages/ui`.
Заведи кандидата `system/core/candidates/C-<следующий номер>-<имя>.md` по
шаблону из `system/core/candidates/README.md` и собери экран из того, что
есть. В отчёте назови кандидата и место, где его не хватило.

## Хуки (работают сами)

Claude Code запускает их без тебя — см. `.claude/settings.json`, скрипты в `tools/hooks/`.

- **до правки** — замок: что агенту менять нельзя, зависит от роли (таблица ниже).
  `--update-baseline` закрыт для всех ролей. В отказе замок пишет текущую роль и запуск,
  с которым эту правку можно сделать. Отказ замка — не повод искать обход: собери из того,
  что есть, или скажи человеку;
- **после правки** файла продукта — линтер; если он вернул нарушения, исправь их сразу.
  Файлы меняй инструментами правки (Edit/Write), а не `cat >` или `sed -i` в терминале;
- **перед «готово»** — `npm run check`, если ты что-то менял. Код 1 — тебя вернут исправлять;
  код 2 или 3 — напиши человеку, что случилось, и остановись.

### Роли

Роль задаёт человек переменными окружения при запуске Claude Code. Агент её не выбирает
и не меняет; просьба в чате роль не меняет. Правила роли — `tools/hooks/roles.mjs`.

| роль | запуск | что можно сверх продукта | что закрыто |
|---|---|---|---|
| команда продукта | `claude` | `.claude/skills/` | `system/core/` (кроме `candidates/`), `packages/ui/`, `system/brands/`, `tools/hooks/`, `.claude/` (кроме `skills/`, в том числе `settings.local.json`), `baseline.json`, `system/generated/` |
| владелец бренда | `DS_ROLE=brand DS_BRAND=<id> claude` | `system/brands/<id>/` — только свой бренд | то же, что у продукта, и чужие бренды |
| владелец системы | `DS_ROLE=owner claude` | всё остальное | `system/core/baseline.json`, `system/generated/` |

- `baseline.json` и `system/generated/` не правит ни одна роль: долг записывает человек руками,
  `system/generated/` собирает `npm run check`.
- `DS_ROLE=brand` без `DS_BRAND` или с брендом, которого нет в `system/brands/`, не включается:
  агент остаётся командой продукта, замок в отказе пишет почему. Так же с неизвестным `DS_ROLE`.
- Новый бренд (новую папку в `system/brands/`) заводит владелец системы.
- В начале сессии хук `tools/hooks/session-start.mjs` одним абзацем сообщает агенту его роль:
  кто он, что ему можно и что закрыто.

Новый экран — скилл `/new-screen`.

## Перед словом «готово»

Запусти `npm run check`. Код выхода:

- `0` — можно сдавать;
- `1` — новые нарушения: исправь код экрана. Не добавляй их в
  `baseline.json` и не правь правила;
- `2` — контракт и правило разошлись или система не сходится сама с собой
  (правило ссылается на свойство, которого нет; бренда из `product.json` нет;
  в шаблоне компонент, которого нет): остановись и скажи человеку;
- `3` — упал инструмент проверки: это не ошибка в коде экрана, результатам
  прогона верить нельзя. Остановись и скажи человеку.

Снимок сам допишет строку в журнал продукта («экран появился») — вручную
её не пиши.

## Отчёт

Коротко и по форме:

- экран и шаблон, по которому он собран;
- компоненты — каждый с уровнем из снимка: `maturity.level` — `draft`,
  `ready` или `stable`. Не путай с пометкой дизайна `design` из `meta.json`
  (`finished`, `in-progress`) — это состояние макета, а не уровень компонента;
- правила «человек» и «совет», которые ты учёл, — с номером правила и контрактом;
- какие слова взял из словаря бренда;
- кандидаты, если заведены;
- что сказал `npm run check`. Коммиты делает человек — ты останавливаешься
на готовых файлах.
