# ds-proto

Прототип дизайн-системы, общей для нескольких брендов: компоненты,
токены, контракты, линтер, уровни зрелости, витрина — и продукт
Merrow Admin, собранный из всего этого.

## Запуск

```
npm install
npm run dev        # проверка + витрина на http://localhost:4321
npm run dev:crm    # продукт Merrow Admin на http://localhost:5173 (второе окно терминала)
```

| команда | что делает |
|---|---|
| `npm run check` | токены → типы (компоненты, продукты, витрина) → линтер → снимок → пакеты брендов. Код 0 — всё чисто, 1 — есть что исправить в продукте, 2 — система не сходится сама с собой, 3 — упал инструмент |
| `npm run lint` | только линтер |
| `npm run typecheck` | проверка типов во всех пакетах |
| `node tools/lint/lint.mjs --update-baseline` | заморозить текущие нарушения как долг. Только решением человека |

## Что где

```
packages/ui/              компоненты (@ds/ui): код, стили, meta.json; формулировки — strings.tsx
apps/docs/                витрина — читает system/ напрямую
apps/crm/                 продукт Merrow Admin (бренд Merrow): product.json — экраны и их шаблоны,
                          rules.json — свои правила команды, cover.jpg — обложка
system/
  core/                   общая база знаний, одна на все бренды
    tokens/               примитивы и роли
    contracts/            правила применения компонентов
    rules/                правила компонентов для линтера, каждое с якорем в контракт
    code-rules.json       общие правила кода продуктов: без голых элементов, без цвета числом…
    patterns/             шаблоны экранов: список, карточка записи, форма, настройки
    candidates/           чего в системе нет
    decisions/            почему устроено так
    baseline.json         разрешённый долг
  brands/<id>/            бренд: brand.json (токены, слова), тон голоса, словарь, изображения,
                          rules.json (словарь как проверка), illustrations/ (картинки и промпты к ним)
  generated/              собирается npm run check: снимок, токены, отчёт линтера
tools/                    сборщики: tokens, lint, snapshot, export
CLAUDE.md                 правила для агента
```

## Как это работает

Компоненты и их правила — общие. Бренд меняет четыре токена (акцент,
шрифт заголовков, два скругления) и слова внутри компонентов. Продукт
живёт под одним брендом. `npm run check` разбирает код и пишет снимок —
из него живут витрина и агент. Уровень зрелости считается по проверкам;
«Нет нарушений» засчитывается, только если все правила компонента запустились
и всё проверено; последний шаг к стабильному — поле «Сверено человеком» в
контракте с датой сверки (ГГГГ-ММ-ДД). Снимок не берёт отчёт линтера, если
код поменялся после прогона или линтер упал.

## Правила: где живут и кто видит

| уровень | файл | действует | кто меняет |
|---|---|---|---|
| общие | `system/core/code-rules.json` | все продукты всех брендов | владелец системы |
| бренда | `system/brands/<id>/rules.json` | продукты бренда | автор текстов, владелец бренда |
| продукта | `apps/<продукт>/rules.json` | один продукт | команда продукта |

Все правила видны в витрине: «Проверки → Правила», на странице продукта
и бренда. Агент получает их в пакете своего бренда: там общие правила,
правила бренда и `rules.json` его продуктов, снимок, отчёт линтера и токены,
срезанные до этого бренда, каркас `src/Page.tsx` продуктов бренда и примеры
шаблонов экранов. Пакет собирается одинаково байт в байт при одном и том же входе.
