# Кандидаты

Чего в системе нет, но уже понадобилось. Один файл — один кандидат:
`C-<номер>-<короткое-имя>.md`. Номер — следующий по порядку.

Заявить может кто угодно: дизайнер, разработчик, агент. Агент обязан
заявить кандидата, если для экрана не хватает компонента, — и собрать
экран из того, что есть, а не рисовать недостающее сам.

Шаблон:

```
# C-002 Название

**Состояние:** заявлен
**Кто заявил:** имя или «агент»
**Дата:** ГГГГ-ММ-ДД
**Где нужен:** экран и место на нём
**Из чего собирается:** чем закрыт пробел сейчас

## Зачем

Что пользователь должен сделать и почему существующие компоненты не подходят.

## Что пробовали

Какие компоненты рассматривали и почему отказались.
```

Состояния: заявлен → разобран → принят (появляется черновик) → сделан;
с любого шага до «сделан» — отклонён (с причиной).

- **заявлен** — файл лежит, никто не разбирал;
- **разобран** — владелец системы посмотрел: хватит ли существующего;
- **принят** — решили делать, появился черновик компонента или свойства;
- **сделан** — компонент вышел и подключён там, где был нужен (поле «Где нужен»).
  Ставит владелец системы. В поле «Из чего собирается» — новый компонент
  вместо прежней замены; в «Решении» — где подключён и какой у компонента
  уровень из снимка. Список «Доделать потом» остаётся: это работа над
  компонентом, кандидат её не держит;
- **отклонён** — с причиной. Файл остаётся, чтобы ту же идею не заявляли заново.

Открытые кандидаты — заявлен, разобран, принят. Закрытые — сделан и отклонён.
Состояние пишется первым словом поля «Состояние», после него можно дату и
пояснение: `сделан — 2026-10-24, владелец системы`.
