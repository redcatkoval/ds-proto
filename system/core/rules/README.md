# Правила линтера

Один файл на компонент. Каждое правило держится за контракт якорем:
номер правила в контракте и его текст дословно. Линтер перед проверкой
ищет этот текст в правиле контракта, а у правила — пометку «Кто следит:
машина». Не нашёл — правило не запускается, прогон заканчивается кодом 2:
контракт и правило разошлись. Так же — если правило называет свойство
(`prop`, ключ `where`), значение `where` или соседа, которых у компонента
нет: свойства читаются из типа `<Имя>Props` в коде компонента.

Виды правил:

| вид | что проверяет |
|---|---|
| max-per-parent | среди соседей одного родителя не больше `max` таких элементов (с `where` — только с этими свойствами) |
| max-per-file | в одном файле экрана не больше `max` |
| order-last | элемент с `where` стоит последним среди соседей того же компонента |
| forbidden-sibling | рядом нет перечисленных компонентов |
| attr-nonempty | свойство `prop` — непустая строка |
| min-items / max-items | в массиве `prop` не меньше / не больше элементов |
| destructive-last | в массиве `prop` элементы с `destructive: true` идут в конце |

Чего машина не знает (значение в переменной, `.map()`, спред) — это
«не проверено», а не «чисто».
